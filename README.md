# 검·인정 교과용도서 선정 문서 작성 웹앱

「검‧인정 교과용도서 선정 계획(안)」의 서식1(선정 평가표)·서식2(평가 총괄표)·서식3(추천 의견서)을
자동 초안 생성 → 인라인 편집 → 인쇄·PDF 저장 → 과목별 자동 집계까지 처리하는 웹앱입니다.
개발 계획서: [교과서선정_문서작성_웹앱_개발계획.md](./교과서선정_문서작성_웹앱_개발계획.md)

- **배포 주소**: https://dacisosl.github.io/choice/
- `main` 브랜치에 push 하면 GitHub Actions가 자동으로 빌드·배포합니다.

## 한눈에 보는 구조

**로그인 없이 쓰고, 평가 자료는 서버에 올라가지 않습니다.**

```
위원 선생님                              총괄 작성 선생님
  과목·출판사·순위 입력                     받은 PDF 올리기
  → 서식1·서식3 초안 → 편집               → 위원명·출판사·점수 자동 추출
  → [PDF로 저장] ───── 메일·메신저 ─────▶  → 서식2 총괄표 집계 + 공식 서식3
                                          → 인쇄·PDF 저장
```

| 대상 | 가입 | 하는 일 |
|---|---|---|
| **위원 교사** | 필요 없음 | 서식1·개인 서식3 작성, 인쇄·PDF 저장 |
| **총괄 작성 교사** | 필요 없음 | 위원들의 서식1 PDF를 올려 서식2·공식 서식3 작성 |
| **학교 담당 교사** | 이메일 가입 1개 | 학교의 선정 대상 과목·과목별 출판사를 등록해 모든 선생님 화면에 반영 |

- 작성한 평가표·총괄표는 **그 컴퓨터의 브라우저에만** 저장됩니다. 서버·데이터베이스로 전송되지 않으며 "제출" 기능도 없습니다.
- 서버에 저장되는 것은 **학교별 과목 목록과 과목별 출판사 목록뿐**입니다.
- 브라우저 자료를 지우면 작성 중인 문서도 사라집니다. [파일로 저장(JSON)]으로 백업하세요.

## 화면

| 화면 | 내용 |
|---|---|
| 서류 작성 | ① 이름·과목·출판사·순위를 넣으면 선정 평가표가 바로 생성(셀 편집, 배점 초과 경고) → ② 추천 의견서 → ③ 인쇄·PDF·JSON 저장 |
| 총괄표 | ① 작성자·과목 입력 + 위원 PDF·JSON 올리기 → [총괄표 생성하기] → ② 평가 총괄표·추천 의견서 확인·편집 → ③ 인쇄·PDF·JSON 저장 |
| 설정 | 담당자 로그인(가입·비밀번호·탈퇴), 선정 과목 관리(목록 붙여넣기·CSV·개별 추가/수정/삭제), 과목별 출판사 관리, 평가기준, 의견 선택지, 문체·목표 총점·AI 키 |

### 의견 작성

서식의 **의견 칸을 클릭**하면 창이 열립니다. 그 안에서 핵심의견을 고르고 → [의견 생성] → 문장을 다듬고 → [적용]까지 한 번에 합니다.
고른 핵심의견은 문서에 함께 저장되어 다시 열면 그대로 체크되어 있습니다.

## PDF에서 점수를 읽어 오는 방식

총괄 화면은 올린 PDF의 **글자(텍스트 레이어)** 를 읽어 표를 복원합니다.

1. 위원이 [인쇄 / PDF 저장] → 인쇄 창의 대상에서 **PDF로 저장**을 고르면 글자가 그대로 들어간 PDF가 만들어집니다. (평가표는 가로, 추천 의견서는 세로로 자동 출력)
2. 총괄 화면에서 그 PDF들을 올리면 `합계` 줄의 숫자 위치를 기준으로 출판사 열을 찾아 위원명·과목·출판사·항목 점수·총점·종합의견을 복원합니다.
3. 항목 점수의 합과 표의 합계가 다르면 경고를 표시하고 합계를 그대로 씁니다.

예비 수단:

- **스캔·사진 PDF** — 글자 정보가 없으면 그림에서 글자를 읽습니다(OCR, `tesseract.js`). 시간이 오래 걸리고 숫자가 틀릴 수 있어 표에서 확인이 필요합니다.
- **JSON 파일** — 위원 화면의 [파일로 저장(JSON)]으로 만든 파일을 올리면 가장 정확합니다.
- **직접 추가** — 위원 이름만 넣고 총괄표 셀에 점수를 직접 입력할 수 있습니다.

## 학교 계정 (선택)

`public/config.json` 에 Firebase 설정이 있으면 학교 담당 선생님이 과목·출판사를 등록해 학교 전체에 공유할 수 있습니다. 설정이 비어 있으면 계정 기능이 꺼지고, 각자 화면에서 출판사를 직접 입력해 씁니다.

1. https://console.firebase.google.com 에서 프로젝트를 만들고 **Firestore Database** 를 생성합니다(위치: asia-northeast3 권장).
2. 프로젝트 설정 › 내 앱 › 웹 앱 추가 후 `firebaseConfig` 의 `apiKey`, `authDomain`, `projectId`, `appId` 를 [`public/config.json`](./public/config.json) 의 `firebase` 에 넣습니다.
3. 빌드 › Authentication › Sign-in method 에서 **이메일/비밀번호** 를 사용 설정합니다.
4. Authentication › 설정 › 승인된 도메인에 `dacisosl.github.io` 를 추가합니다.
5. Firestore 화면에서 `databaseId` 와 같은 데이터베이스를 고른 뒤 규칙 탭에 [`firebase/firestore.rules`](./firebase/firestore.rules) 전체를 붙여 넣고 게시합니다.
6. 사이트의 설정 › 담당자 로그인에서 **학교 등록(가입)** 을 하고, 정한 **학교 아이디**(예: `haemil-high`)를 선생님들께 알려 줍니다.
7. 설정 › 선정 과목 관리 → 과목별 출판사 관리 순서로 올해 목록을 등록합니다.

선생님들은 설정 › 담당자 로그인 화면에서 학교 아이디만 넣으면 과목·출판사가 채워집니다. 아이디는 브라우저에 기억됩니다. 학교 아이디를 쓰지 않아도 과목명과 출판사를 직접 적어 바로 작성할 수 있습니다.

### 저장되는 문서

`schools/{학교아이디}` 문서 1건입니다.

| 필드 | 내용 |
|---|---|
| `schoolName`, `schoolId` | 학교 이름과 공유용 아이디 |
| `ownerUid` | 담당 선생님 계정 식별자 (이 계정만 수정·삭제 가능) |
| `subjects`, `publishers` | 선정 대상 과목, 과목별 출판사 |

### 개인정보

- 수집 항목은 **담당 선생님 이메일**(로그인·비밀번호 재설정용)과 학교 이름·아이디뿐입니다. 가입하지 않는 선생님의 정보는 수집하지 않습니다.
- 위원별 점수·의견·총괄표는 서버에 저장되지 않습니다.
- 설정 › 학교 계정에서 **비밀번호 변경**, **비밀번호 재설정 메일**, **회원 탈퇴**(계정과 학교 자료를 함께 즉시 삭제)를 할 수 있습니다.
- 전문은 앱의 `#/privacy` 화면(개인정보 처리방침)에서 볼 수 있습니다.

## 얼마나 쓸 수 있나 (무료 한도)

평가 자료가 서버로 가지 않으므로 서버 부담은 **학교 문서 1건을 읽고 쓰는 것**뿐입니다. Firebase 무료(Spark) 요금제 기준입니다.

| 항목 | 무료 한도(하루) | 이 앱의 사용량 | 감당 규모 |
|---|---|---|---|
| 문서 읽기 | 50,000회 | 선생님이 앱을 열 때 학교 문서 1~2회 | 하루 **2만 명 접속**까지 여유 |
| 문서 쓰기 | 20,000회 | 담당자가 과목·출판사를 저장할 때만(2초 모아서 1회) | 학교 수백 곳이 같은 날 등록해도 여유 |
| 저장 용량 | 1 GiB | 학교 문서 1건당 수십 KB | 학교 **1만 곳** 이상 |
| 가입 계정 | 제한 없음(이메일/비밀번호) | 학교당 1개 | 제한 없음 |

- 선생님 수가 아니라 **학교 수**가 기준입니다. 한 학교에서 선생님 100명이 써도 학교 문서 읽기만 늘어납니다.
- 한도를 넘겨도 유료 전환(Blaze) 시 읽기 10만 회에 약 0.06달러 수준이라 비용이 크지 않습니다.
- 사이트 자체는 GitHub Pages(정적 호스팅)라 접속량 부담이 거의 없습니다.

## AI 문장 생성 (선택)

설정 › 문서·AI 설정에서 **OpenRouter API 키**를 넣으면 핵심의견을 바탕으로 문장을 생성합니다.
키는 입력한 컴퓨터에만 저장되며, 키가 없거나 호출이 실패하면 규칙 기반 문장으로 자동 대체되어 작업이 멈추지 않습니다.

## 운영 순서 (권장)

1. (학교 계정을 쓸 때) 담당 선생님이 학교 등록 → 과목·출판사 입력 → 학교 아이디 공지.
2. 위원 선생님들이 서식1·서식3을 작성하고 **PDF로 저장**해 총괄 선생님께 전달.
3. 총괄 선생님이 PDF를 올려 서식2·서식3을 만들고 확인·인쇄.

## 개발

```bash
npm install
npm run dev      # http://localhost:5173/choice/
npm run build    # dist/
```

React 18 + Vite + TypeScript. 외부 UI 라이브러리 없이 `src/styles.css` 한 파일로 화면·인쇄(@media print, 서식1 A4 가로 / 서식2·3 세로) 스타일을 관리합니다.

```
src/
  seed.ts                 과목 목록·기본 평가기준·의견 선택지 초기 데이터
  lib/scoring.ts          순위→점수 초안, 합계·평균·순위(동점) 계산
  lib/ai.ts               OpenRouter 호출 + 규칙 기반 폴백 문장
  lib/form1Parse.ts       글자 조각 → 서식1·서식3 표 복원 (순수 함수)
  lib/pdfImport.ts        PDF 텍스트 레이어·OCR 읽기, JSON 가져오기
  store/storage.ts        이 컴퓨터 저장(localStorage)
  store/school.ts         학교 계정·학교별 과목/출판사 공유 (Firebase)
  components/Form*.tsx    서식1·2·3 (화면·인쇄 공용)
  components/OpinionModal 의견 칸 클릭 → 핵심의견 선택·생성·적용
  pages/                  Start · Personal · Compile · Settings · Guide · Privacy
```
